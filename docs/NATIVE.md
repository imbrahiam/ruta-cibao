# Native apps: Kotlin Multiplatform core, SwiftUI and Compose shells

Status: in progress. The Expo app has been removed; the
native apps are the citizen app.

## Why

Expo's tooling caps what the product can do on the platform: widgets, Live
Activities, App Intents, CarPlay / Android Auto, MapKit, background location
and first-class gestures all need native code, and debugging and profiling
through the RN layer is worse than Xcode and Android Studio on their own. Performance
is not the reason.

The cost of two native UIs is accepted. Business logic is shared once,
in Kotlin. UI is written twice, on purpose.

## Shape

```
packages/contracts/            Zod + oRPC contract (unchanged, source of truth)
  generated/openapi.json       generated from the contract, committed
  scripts/openapi.ts           contract  -> openapi.json
  scripts/kotlin.ts            openapi.json -> Kotlin models + API client
packages/shared/messages/      es.json catalogue (source of truth for copy)

packages/kmp/                  Kotlin Multiplatform (Gradle root is native/)
  api/                         generated client: @Serializable models, RutaApi, ApiError
  core/                        platform seams: config, logging, secure store, dispatchers
  data/                        session (Better Auth), repositories, offline db, outbox
  presentation/                shared ViewModels: StateFlow<UiState> + intent functions
  shared/                      umbrella: DI graph; the only module exported to iOS (RutaKit)

apps/android/                  Jetpack Compose app (consumes :kmp:shared)
apps/ios/                      SwiftUI app, project generated by XcodeGen (links RutaKit)
native/                        Gradle root: settings, wrapper, version catalog
  build-logic/                 Gradle convention plugins (one place for targets/flags)
```

**Mirrored features.** Every feature has the same name in three places:

| Layer | Path |
|---|---|
| Shared ViewModel | `packages/kmp/presentation/src/commonMain/kotlin/rutacibao/presentation/<feature>/` |
| Android | `apps/android/src/main/kotlin/rutacibao/android/feature/<feature>/` |
| iOS | `apps/ios/Sources/Features/<Feature>/` |

A feature only counts as done when it works on both platforms. The checklist below tracks progress
per platform.

## Architecture

Layered, unidirectional, one direction of dependency:

```
SwiftUI View / Composable  ->  ViewModel (shared)  ->  Repository (shared)  ->  RutaApi / SQLDelight
        renders UiState          owns state, intents      cache + network         generated / local
```

- **UiState is a single immutable data class per screen**, exposed as
  `StateFlow`. Screens render it and call intent functions (`refresh()`,
  `select(id)`). No business logic in Swift or Compose.
- **ViewModels are `androidx.lifecycle.ViewModel` in commonMain.** Android gets
  lifecycle for free. On iOS a small `@Observable` wrapper per screen collects
  the flow with SKIE's `AsyncSequence` bridge and calls `clear()` on deinit.
- **Repositories** return `Flow` for observed data and `suspend` + `Result`-style
  sealed outcomes for commands. Each mutation sends an idempotency `requestId`
  (the contract already requires it).
- **Errors** are typed: `ApiError(code, status, message, data)` decoded from
  oRPC's error body. UI maps `code` to a catalogue key, so the server never
  sends copy to the client.
- **DI**: Metro (compile-time graph, KMP). One `AppGraph` in `:kmp:shared`;
  platform bindings (`PlatformBindings`) are supplied by each app at startup.
- **Platform seams** use interfaces bound in the graph, not `expect class` all over:
  `SecureStore` (Keychain / Keystore AES-GCM), `AppConfig`, `Connectivity`.
  `expect/actual` only for leaf functions (`httpEngine()`, `platformName()`).

## Contract to native types

The OpenAPI document generated from the contract is 75 operations with mostly inline schemas.
`openapi-generator` turns that into `InlineObject123` names and wraps the client in its own HTTP
types, so we use a ~500-line generator we own (`packages/contracts/scripts/kotlin.ts`) instead:

- Operation `places.detail` → `api.places.detail(...)`; output type `PlacesDetailOutput`,
  inline objects become nested classes (`PlacesDetailOutput.Photo`).
- `anyOf [T, null]` → `T?`; string `enum`/`const` sets → Kotlin `enum class` with
  `@SerialName`; `date-time` → `kotlin.time.Instant`; other unions → `JsonElement`.
- Path, query (oRPC sends GET input as query) and JSON bodies are handled per operation.
- Swift sees all of this through SKIE (sealed → enum, suspend → async, Flow → AsyncSequence).

Pipeline: `bun run gen:native` writes `openapi.json` and the Kotlin sources (committed).
CI runs it and fails on a diff, and `oasdiff breaking` blocks incompatible changes to a
released API.

## Maps

Each platform uses its own native map: MapKit on iOS, Google Maps on Android. MapKit
can't apply the "gris" style JSON, so on iOS that look becomes `mutedStandard`. If the map later needs identical styling or offline vector tiles,
the alternative is MapLibre Native on both, decided per feature, not up front.

## Phases

0. **Foundation** — branch, Gradle + convention plugins, generator, `:kmp:*` modules,
   Android + iOS shells that build, one vertical slice (consultations list) on both.
1. **Platform seams** — session/auth (phone + email OTP via Better Auth REST),
   secure store, config per variant (dev / preview / production ids and schemes),
   strings + tokens generators, error mapping.
2. **Map** — map screen, layers, markers + clustering (port `supercluster` logic to
   commonMain), place detail sheet, search, directions, location permission.
3. **Contribute** — place, traffic, safety reports, photo upload, pick-location;
   offline db + outbox with background sync (WorkManager / BGTaskScheduler).
4. **Consultations, passport, account** — remaining screens, notifications + push.
5. **Native-only wins** — widgets, Live Activities for traffic/route,
   App Intents, CarPlay / Android Auto, background location where justified.
6. **Cutover** — parity checklist green on both, store builds (the Expo app is already removed).

## Local testing

The real dev server, as the README describes: `docker compose -f infra/docker-compose.yml up -d`,
`bun run db:migrate`, `bun run db:seed:demo`, `bun run dev`. Demo numbers (`LOCAL_DEMO_PHONES`) sign in
with `LOCAL_DEMO_OTP`, and both are refused in production. Debug builds have test hooks for simulator
screenshot runs, compiled out of Release:

- `SIMCTL_CHILD_RUTA_DEBUG_SESSION="better-auth.session_token=…"` seeds the session.
- `SIMCTL_CHILD_RUTA_DEBUG_TAB=map|consultations|contributions|account` opens a tab.
- `SIMCTL_CHILD_RUTA_DEBUG_SLUG=<slug>` opens a consultation; `SIMCTL_CHILD_RUTA_DEBUG_COMPOSE=search` opens map search;
  `SIMCTL_CHILD_RUTA_DEBUG_SCROLL=bottom` opens scroll views at their end (tab-bar clearance check).
- `SIMCTL_CHILD_RUTA_DEBUG_COMPOSE=consultation|traffic|place` opens a form; `claim|edit` opens the business form on a place sheet
  (open the sheet with `xcrun simctl openurl booted rutacibao-dev://s/place/<slug>`).
- `SIMCTL_CHILD_RUTA_DEBUG_TRAFFIC=select|still` opens the first road report that isn't yours (needs the session hook for `still`),
  and `still` also answers "Sigue ahí" after 5 s. Android: `adb shell am start ... --es ruta_debug_traffic select|still`.

- `SIMCTL_CHILD_RUTA_DEBUG_TAB=gestion` opens Cuenta with Gestión (staff only) pushed. `SIMCTL_CHILD_RUTA_DEBUG_STEPUP=1` shows the
  second-factor sheet (the local demo staff skip the step-up on the server). `SIMCTL_CHILD_RUTA_DEBUG_GESTION=approve|reject` with
  `..._GESTION_KIND=<place|photo|claim|traffic|consultation|contentReport|placeReport>` decides the first card of that kind (a reject
  also takes `..._GESTION_NOTE=<text>` and `..._GESTION_SEND=1`); `=report` opens the latest weekly PDF.
  `SIMCTL_CHILD_RUTA_DEBUG_REPLY=<text>` (+ `..._REPLY_SEND=1`) fills and sends the staff reply on an open consultation.

Simulator builds sign ad hoc (`CODE_SIGN_IDENTITY[sdk=iphonesimulator*] = -`), because the Keychain
refuses unsigned apps.

## Category look on iOS

Categories are database rows, so the admin panel stays in charge. iOS maps the Lucide icon to an SF
Symbol and the admin hex to the *nearest system colour by hue* (grey under 40% saturation, brown for
a dark orange). A colour changed in the panel shows on the iPhone without a release, and stays native
(dark mode, Increase Contrast). Android and the web use the hex as is.

## Design language

Social-app polish on a civic product: Threads-style feed (category avatar, thread line, plain-text
metrics, hairlines instead of cards), big confident titles, one dominant action per screen, Liquid
Glass on iOS 26 and Material 3 on Android. References were pulled from Mobbin (Threads feed; Shelf
and Walmart OTP screens; Cash App and Bump map sheets). Every pattern was kept for a reason, not because it looked nice.

On iOS, contribution action tiles and the badges in Mis aportes / Avisos share the kind's
colour gradient (blue for consultations, orange for road reports, green for places).
The place sheet uses the category badge's gradient for Cómo llegar, with contrast-aware ink
instead of a stronger glass tint. External maps is an icon menu beside save and share;
the horizontal Experiencias row opens a separate sheet with the place's thread and composer.

Cuenta opens the profile editor from the identity card, with separate saved-place and passport
shortcuts above the settings rows. Saved places open their map sheet instead of acting as static
rows. Aportes keeps Mis aportes / Avisos pinned while scrolling; consultation entries are native
buttons opening their thread. The photo viewer's paging surface extends behind both safe areas,
while its close control remains inside the safe area.

References consulted through Mobbin MCP:
[Airbnb's profile menu](https://mobbin.com/screens/dc125dc8-e3de-45d4-a8fc-116f2dfa2515),
[Pangea's compact shortcuts](https://mobbin.com/screens/b136f6f3-2734-42de-9973-55ea0ce9c3bb),
and [Nextdoor's activity tabs](https://mobbin.com/screens/4ab1fb9f-e6f8-4dbc-88fa-9f6f82ca31f1).
Button labels choose whichever of black or white has the higher WCAG contrast against the
resolved background colour. Contribution-tile glyphs stay white in light mode, and use
contrast-aware ink in dark mode; their labels remain outside the colour fill.

## Map look and camera mode (iOS)

- Apple's full-colour standard style with realistic elevation (3D buildings and terrain when tilted),
  a satellite + roads toggle (the colourful option where Apple has no land cover, which is most of the
  province) and our own 2D/3D, locate and camera buttons.
- Camera mode (`CameraMode.swift`): ARKit world tracking aligned to gravity and compass heading. The
  closest 12 places within 2 km float at their real bearing (distance compressed to 8–40 m) as cards
  rendered from SwiftUI; tap one to go back to the map with it open. Needs a device (the simulator
  shows the "unsupported" notice). `RUTA_DEBUG_COMPOSE=camera|3d` open it or a pitched map.

## Push notifications (APNs)

- Server (`apps/web/src/lib/push.ts`): token-based APNs over HTTP/2 (ES256 provider JWT, renewed every
  40 min). Same device table, encryption, idempotent subscribe and audit trail as before; the ticket
  keeps APNs' `apns-id` (`provider_message_id`). APNs answers synchronously, so a
  410/`BadDeviceToken` disables the device on the spot and the receipts job is a no-op. Config:
  `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_PRIVATE_KEY` (.p8 text), `APNS_TOPIC`, `APNS_ENVIRONMENT`.
  Android devices register but wait for FCM (not wired yet).
- Shared (`PushRepository`): stable installation id, binds the platform token to the signed-in
  account, re-binds after sign-in, unbinds before sign-out.
- iOS (`App/Push.swift`): `aps-environment` entitlement (development/production per config), asks
  right after sign-in, refreshes the token on each launch, foreground banners refresh Avisos, a tap
  routes through `DeepLinks` (`/s/<kind>/<ref>`, `/contributions`), which also handles
  `rutacibao://` links. Test a tap path with `xcrun simctl openurl booted rutacibao-dev://s/consultation/<slug>`
  and a delivery with `xcrun simctl push booted do.rutacibao.app.dev payload.apns`.

## Rules that carry over

User-facing copy comes only from the catalogue. Mutations send idempotency ids. PII
never goes to logs. Honour reduced motion, and never signal state by colour or motion alone.
Tap targets are at least 44pt/48dp.

## Editor setup (Cursor / VS Code)

`.vscode/extensions.json` lists the extensions; Cursor offers them on open.
Two language servers need a step the marketplace doesn't cover:

- **Swift** (hover types, go to definition): `swiftlang.swift-vscode` runs
  sourcekit-lsp, which learns the Xcode project from `apps/ios/buildServer.json`.
  Create it once per machine (it holds local paths, so it's gitignored), then
  build once into Xcode's default DerivedData:
  ```bash
  brew install xcode-build-server
  cd apps/ios && xcode-build-server config -project RutaCibao.xcodeproj -scheme RutaCibao
  xcodebuild -project RutaCibao.xcodeproj -scheme RutaCibao \
    -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
  ```
  Rebuild after adding files so new ones resolve.
- **Kotlin**: JetBrains' Kotlin LSP isn't on the Open VSX marketplace; install
  the `.vsix` for your platform from the
  [kotlin-lsp releases](https://github.com/Kotlin/kotlin-lsp/releases). It
  imports the Gradle build from `native/` (needs JDK 17+); its support
  for Kotlin Multiplatform source sets is still partial, so `commonMain` code
  resolves best.
